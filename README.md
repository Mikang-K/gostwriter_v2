# Ghostwriter v2 사용 설명서

Ghostwriter는 AI와 함께 소설을 쓰는 개인 작업실입니다. 작품의 인물과 세계관을 정하고, 원하는 전개를 입력하면 다음 회차를 생성합니다. 저장한 회차를 다시 읽거나 마지막 회차를 되돌릴 수 있습니다.

**기본 사용은 내 PC의 모델로 생성하고 내 PC의 데이터베이스에 저장하는 방식입니다.** 외부 모델을 사용하려면 별도 설정과 요청별 허용이 필요합니다. 현재는 본인용 로컬 시험판이며, 생성된 글의 설정·문장·완결성은 직접 확인해야 합니다.

처음 사용한다면 **1. 처음 한 번 준비하기**부터 진행하세요. 설치를 마쳤다면 **2. 매번 작업실 열기**부터 시작하면 됩니다.

## 1. 처음 한 번 준비하기

아래 안내는 **Windows PowerShell** 기준입니다. 명령은 모두 Ghostwriter 프로젝트 폴더에서 실행합니다. 터미널은 명령을 입력하는 창을 뜻합니다.

### 필요한 프로그램

| 프로그램 | 용도 |
|---|---|
| Node.js 24 | 작업실 화면 실행 |
| uv와 Python 3.13 | 글 생성·저장 기능 실행 |
| Ollama | 내 PC에서 AI 모델 실행 |

기본 사용에는 외부 DB 계정이나 Gemini API 키가 필요하지 않습니다. 모델을 내려받고 프로그램을 설치할 때는 인터넷 연결이 필요합니다.

### 프로그램 파일과 모델 준비

프로젝트 폴더에서 아래 명령을 차례로 실행합니다.

```powershell
npm.cmd ci
uv sync --project backend --locked
ollama pull gemma3:4b-it-q4_K_M
```

처음에는 설치와 모델 다운로드에 시간이 걸립니다. 완료 후 Ollama를 실행한 상태로 둡니다. 아래 명령으로 모델 이름이 표시되는지 확인할 수 있습니다.

```powershell
ollama list
```

### 작업실 암호 준비

```powershell
npm.cmd run db:local
```

`PostgreSQL ready`가 표시되면 저장 기능이 준비된 것입니다. 이 터미널은 닫지 않습니다.

처음 실행하면 `backend/.env.local` 파일에 작업실 암호와 저장소 연결 정보가 만들어집니다. 편집기로 파일을 열어 **`APP_PASSWORD=` 오른쪽의 값**을 확인하세요. 이 값이 로그인 암호입니다. `DATABASE_URL`에 들어 있는 DB 암호와는 다릅니다.

기존 설정 파일은 자동으로 덮어쓰지 않습니다. 모델 설정을 직접 추가할 경우 다음 값을 사용하고, 기존 `DATABASE_URL`과 `APP_PASSWORD`는 유지하세요. 아래 모델 설정은 현재 기본값과 같습니다.

```dotenv
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=gemma3:4b-it-q4_K_M
CONTEXT_WINDOW=8192
MAX_OUTPUT_TOKENS=1024
ENABLE_CLOUD=false
```

이제 아래 실행 안내의 **터미널 B**부터 진행합니다.

## 2. 매번 작업실 열기

Ollama를 실행하고, 프로젝트 폴더에서 터미널 세 개를 엽니다. 각 명령은 실행한 채로 유지합니다.

| 순서 | 터미널 | 실행할 명령 | 하는 일 |
|---|---|---|---|
| 1 | A | `npm.cmd run db:local` | 저장소 열기 |
| 2 | B | `npm.cmd run dev:api` | 글 생성·저장 기능 켜기 |
| 3 | C | `npm.cmd run dev` | 작업실 화면 켜기 |

터미널 A에서 이미 `PostgreSQL ready`가 표시되어 있다면 같은 명령을 다시 실행하지 않습니다.

브라우저에서 **http://localhost:3000**을 엽니다. **작업실 암호**에 앞서 확인한 `APP_PASSWORD` 값을 입력하고 **작업실 열기**를 누릅니다.

접속 주소는 `localhost:3000`을 사용하세요. `127.0.0.1:3000`으로 접속하면 저장 요청이 거절될 수 있습니다. 화면이 열려도 터미널 A·B를 닫으면 저장과 생성 기능을 사용할 수 없습니다.

## 3. 첫 작품 만들기

서재에서 **새 작품**을 누릅니다. 처음에는 제목과 핵심 설정을 짧게 적어 시작해 보세요.

| 입력 항목 | 적을 내용 | 예시 |
|---|---|---|
| 작품 제목 | 서재에 표시할 작품 이름 | 달빛의 문 |
| 장르 | 이야기의 종류와 분위기 | 미스터리 판타지 |
| 언어 | 생성할 글의 언어 | 한국어 |
| 목표 회차 | 예상 분량. 미정이면 비워 둡니다. | 10 |
| 세계관 | 이야기에서 지켜야 할 규칙 | 달빛이 닿아야 문이 열린다. |
| 작가 노트 | 전개·묘사·문체에 관한 요청 | 대사는 짧게, 풍경은 차분하게 묘사한다. |
| 등장인물 | 이름·성격·말투·배경 등 | 하린: 신중하며 낯선 사람에게 존댓말을 쓴다. |
| 문체 참고 글 | 참고할 짧은 글 | 원하는 문체의 예문 |

**인물 추가**로 최대 10명까지 등록할 수 있습니다. **문체 참고 글**을 펼치면 참고 글을 최대 3개 입력할 수 있습니다. 현재 품질 검증은 한국어를 중심으로 진행했습니다.

입력이 끝나면 **작품 만들기**를 누릅니다. 이 단계에서는 작품 설정만 저장되며, 소설 본문은 다음 단계에서 생성합니다.

## 4. 회차 생성하고 이어 쓰기

### 첫 회차 생성

1. **전개 방향**에 이번 장면에서 일어날 일을 적습니다.
2. **생성 모델**은 **로컬 모델**로 둡니다.
3. **첫 회차 생성**을 누릅니다.
4. 글이 표시된 뒤 **원고 저장 완료**가 나올 때까지 기다립니다.

전개 방향은 다음처럼 구체적으로 적을 수 있습니다.

> 하린이 달빛 아래에서 낡은 문을 발견한다. 문을 바로 열지 않고 주변을 살피는 장면을 짧게 써 줘.

### 화면의 상태 읽기

| 표시 | 의미 |
|---|---|
| 모델에 연결 중 | 모델을 준비하거나 첫 문장을 기다리는 중입니다. |
| 본문 생성 중 | 글이 차례로 표시됩니다. 아직 확정 원고가 아닙니다. |
| 본문 생성 완료 · 상태 정리 중 | 인물 상태와 사건을 다음 회차에 사용할 기억으로 정리합니다. |
| 원고 저장 완료 | 본문과 이야기 기억이 함께 저장되어 회차가 확정되었습니다. |

**글이 끝까지 보이는 것과 저장 완료는 다릅니다.** 저장 완료 표시와 회차 수를 확인한 뒤 작업을 마치세요. 처음 모델을 불러올 때는 다음 생성보다 오래 걸릴 수 있습니다.

### 다음 회차 생성

확정된 글을 읽고 **전개 방향**을 새로 적은 뒤 **다음 회차 생성**을 누릅니다. 추천 전개가 표시되면 선택해 입력란에 넣고 수정할 수도 있습니다.

왼쪽 **회차** 목록을 누르면 이전 원고를 읽을 수 있습니다. **이야기 기억**을 펼치면 현재 줄거리와 기록된 인물 상태·복선 개수를 확인할 수 있습니다.

### 작품 설정 수정

**작품 설정**을 펼쳐 세계관·작가 노트·인물 등을 수정한 뒤 **설정 저장**을 누릅니다. 입력만 하고 화면을 닫으면 변경 사항이 저장되지 않습니다. 설정을 바꿔도 이미 저장된 회차 본문이 자동으로 다시 작성되지는 않습니다.

## 5. 중단·실패·되돌리기

### 생성을 멈추고 싶을 때

**생성 중단**을 누릅니다. 중단한 글은 확정 회차에 추가되지 않으며, 보존된 내용은 **미확정 초안**에서 확인합니다. 다음 생성을 누르면 새 요청으로 시작합니다.

### 글은 나왔는데 저장에 실패했을 때

완성된 본문이 남아 있으면 **상태 저장 재시도** 버튼이 표시됩니다. 이 버튼은 기존 본문으로 이야기 기억 정리와 저장을 다시 시도합니다. 본문을 새로 쓰지는 않습니다.

버튼이 없다면 본문 생성 자체가 끝나지 않았을 수 있습니다. 오류 안내와 초안을 확인하고, 필요한 문장은 복사해 둔 뒤 다시 생성하세요. 출력 길이 제한에 걸린 글도 자동 확정되지 않습니다. 같은 문제가 반복되면 전개 방향에 더 짧은 분량을 요청해 보세요.

### 새로고침하거나 연결이 끊겼을 때

같은 브라우저 탭에서 작품을 다시 열면 저장된 요청 상태를 확인합니다. 이미 완료된 회차는 다시 생성하지 않고 불러옵니다. 실패한 요청은 보존된 초안과 재시도 가능 여부를 확인합니다.

**미확정 초안을 복구할 때는 같은 탭을 유지하세요.** 탭을 닫거나 로그아웃하면 초안을 다시 찾기 위한 화면의 정보가 사라질 수 있습니다. 저장 완료된 회차는 다음 로그인에서도 열람할 수 있습니다.

### 마지막 회차를 취소하고 싶을 때

**마지막 회차 되돌리기**를 누르면 마지막 회차를 현재 원고에서 제외하고 이야기 기억을 그 회차 이전으로 되돌립니다. 직접 작성한 세계관과 고정 인물 설정은 유지합니다.

화면에 다시 실행하는 버튼은 없으므로, 남겨 둘 문장이 있다면 먼저 별도 파일에 복사하세요.

## 6. 완결·보관·종료하기

| 하고 싶은 일 | 사용할 기능 |
|---|---|
| 마무리 회차를 생성하며 끝내기 | **에필로그 생성**. 확정된 회차가 있을 때 사용할 수 있으며, 저장이 완료되면 완결됩니다. |
| 추가 생성 없이 끝내기 | **생성 없이 완결** |
| 작업 목록에서 따로 보관하기 | **작품 보관**. 서재의 **보관한 작품 보기**에서 다시 열 수 있습니다. |
| 보관한 작품을 작업 목록으로 돌리기 | 작품을 열고 **보관 해제** |

완결된 작품은 다음 회차를 생성할 수 없습니다. 마지막 회차를 되돌리면 해당 회차 이전 상태로 돌아갑니다. 작품 보관은 원고 삭제가 아닙니다.

작업을 마칠 때는 다음 순서로 종료합니다.

1. 생성 중이라면 저장 완료를 기다리거나 **생성 중단**을 누릅니다.
2. 필요한 초안을 복사하고 작품 설정을 저장합니다.
3. 화면 위쪽 **로그아웃**을 누릅니다.
4. 터미널 C → B → A 순서로 각각 `Ctrl+C`를 눌러 종료합니다.

확정된 원고와 저장한 설정은 프로그램을 종료해도 남습니다. 다음 사용 시 **2. 매번 작업실 열기**를 따르면 됩니다.

## 7. 내 원고는 어디에 저장되나요?

기본 실행에서는 원고·인물·이야기 기억을 내 PC의 PostgreSQL 데이터베이스에 저장합니다. 브라우저 방문 기록이나 화면 파일만으로는 원고를 백업할 수 없습니다. 외부 DB 주소를 직접 설정했다면 그 서버에 저장됩니다.

새 설치의 기본 데이터 폴더는 Windows `%LOCALAPPDATA%/ghostwriter-v2/postgres`입니다. 실제 경로는 `.cache/development-db.json` 파일의 `databaseDir` 값으로 확인합니다.

**이 작업 폴더에 남아 있는 기존 검증용 DB는 임시 폴더를 사용할 수 있습니다.** 임시 경로라면 개인 원고의 장기 보관용으로 사용하기 전에 저장 위치와 백업을 준비하세요. 기존 데이터는 자동으로 이동하지 않습니다.

`backend/.env.local`과 `.cache/development-db.json`에는 암호와 연결 정보가 있습니다. 다른 사람에게 보내거나 공개 저장소에 올리지 마세요. 이 파일을 지우면 같은 저장소에 다시 연결하기 어려워질 수 있습니다.

화면에는 원고 파일 내보내기 기능이 없습니다. 필요한 본문은 복사해 별도 문서로 보관할 수 있습니다. 작품 설정까지 보존하려면 아래의 DB 백업을 사용합니다.

<details>
<summary>전체 데이터 백업·복원 안내</summary>

DB를 실행한 상태에서 PostgreSQL의 `pg_dump`, `createdb`, `pg_restore` 도구가 필요합니다. DB와 호환되는 버전을 사용합니다. 아래 명령은 기본 로컬 실행 설정 기준입니다.

```powershell
pg_dump --host=127.0.0.1 --port=55432 --username=ghostwriter --password --dbname=ghostwriter_v2 --format=custom --file=ghostwriter-backup.dump
```

명령이 묻는 암호는 작업실 로그인 암호가 아닌 **DB 암호**입니다. `backend/.env.local`의 `DATABASE_URL`에서 확인하며, 명령 인자나 채팅에 적지 않습니다. 백업 파일은 개인 원고가 들어 있으므로 별도로 안전하게 보관하세요.

복원은 비어 있는 별도 DB에 진행합니다.

```powershell
createdb --host=127.0.0.1 --port=55432 --username=ghostwriter --password ghostwriter_restore
pg_restore --host=127.0.0.1 --port=55432 --username=ghostwriter --password --dbname=ghostwriter_restore --no-owner ghostwriter-backup.dump
```

복원 후 `backend/.env.local`의 `DATABASE_URL`이 복원한 DB를 가리키도록 설정하고 터미널 B를 다시 실행합니다. 작품과 회차가 보이는지 확인하세요. 백업 복원 절차의 실제 운영 검증은 아직 완료하지 않았습니다.

</details>

## 8. 문제가 생겼을 때

| 증상 | 해 볼 일 |
|---|---|
| `npm`, `uv`, `ollama` 명령을 찾을 수 없음 | 필요한 프로그램을 설치했는지 확인하고 터미널을 새로 엽니다. PowerShell에서는 `npm.cmd`를 사용합니다. |
| 브라우저에 화면이 나오지 않음 | 터미널 C가 실행 중인지 확인하고 `http://localhost:3000`을 다시 엽니다. |
| 암호가 맞지 않음 | `backend/.env.local`의 `APP_PASSWORD`를 확인합니다. 연속으로 틀렸다면 잠시 기다렸다 다시 시도합니다. |
| API 연결 실패 | 터미널 A가 준비된 뒤 B를 실행했는지 확인합니다. B가 종료되었다면 `npm.cmd run dev:api`를 다시 실행합니다. |
| 저장 요청이 거절됨 | 접속 주소를 `http://localhost:3000`으로 맞춥니다. |
| 모델이 없거나 생성이 시작되지 않음 | Ollama를 실행하고 `ollama list`에 `gemma3:4b-it-q4_K_M`이 표시되는지 확인합니다. 모델 설정을 바꿨다면 그 이름과 일치해야 합니다. |
| 생성 시간이 초과됨 | 오류와 초안을 확인합니다. 다른 모델 작업을 마친 뒤 짧은 장면으로 다시 시도해 보세요. |
| 설정이 너무 길다는 안내 | **작품 설정**에서 세계관·작가 노트·문체 참고 글을 간추려 저장합니다. |
| 로컬 모델이 다른 작업을 처리 중임 | 다른 작품이나 탭에서 실행한 생성이 끝난 뒤 다시 시도합니다. |
| 다른 작업으로 내용이 바뀌었다는 안내 | 새로고침해 최신 상태를 불러옵니다. 같은 작품을 여러 탭에서 수정하는 것을 피합니다. |
| 포트가 이미 사용 중임 | 이미 실행한 터미널을 확인합니다. 동일한 저장소·화면·API를 중복 실행하지 않습니다. |

모델이 느리거나 자주 멈추면 화면 위쪽 **생성 기록**에서 최근 7일의 첫 응답 시간·처리 시간·모델·상태를 확인할 수 있습니다. `미측정`은 측정값이 없다는 뜻입니다.

## 9. 선택 기능과 참고 문서

<details>
<summary>Gemini 등 외부 모델 사용하기</summary>

기본값은 외부 모델 사용 안 함입니다. Gemini를 사용하려면 `backend/.env.local`에 아래 값을 설정하고 터미널 B를 다시 실행합니다.

```dotenv
ENABLE_CLOUD=true
GEMINI_MODEL=사용할_모델명
GEMINI_API_KEY=발급받은_API_키
```

화면에서 **생성 모델 → Gemini**를 선택하고 **이번 요청의 외부 모델 사용 허용**을 체크합니다. 허용은 요청마다 다시 선택합니다. 로컬 모델을 선택한 상태에서 허용하면 로컬 생성이 시작되기 전 실패했을 때 외부 모델로 전환될 수도 있습니다.

허용한 요청에서는 작품 설정·인물·최근 원문·요약·전개 방향·생성 본문이 생성 또는 상태 정리를 위해 외부로 전송될 수 있으며 비용이 발생할 수 있습니다. 첫 본문이 나온 뒤 실패한 경우에는 다른 모델의 글로 이어 붙이지 않습니다. 실제 Gemini 호출 검증은 아직 완료하지 않았습니다.

</details>

<details>
<summary>Docker로 실행하기 — 별도 실행 환경</summary>

기본 로컬 실행을 대신해 사용하는 방법입니다. Docker와 호스트 Ollama가 필요하며, 현재 환경에서는 이미지 빌드와 컨테이너 기동을 검증하지 못했습니다. 기존 화면·API를 종료한 뒤 진행합니다.

처음 한 번 아래 명령으로 설정 파일을 만듭니다. 기존 파일은 덮어쓰지 않습니다.

```powershell
if (Test-Path .env.compose) { throw ".env.compose already exists" }
$dbPassword = [guid]::NewGuid().ToString("N")
$loginPassword = [guid]::NewGuid().ToString("N")
@("POSTGRES_PASSWORD=$dbPassword", "APP_PASSWORD=$loginPassword", "OLLAMA_MODEL=gemma3:4b-it-q4_K_M") |
  Set-Content -Encoding ascii .env.compose
```

이후 실행과 종료 명령은 다음과 같습니다.

```powershell
docker compose --env-file .env.compose up --build
```

화면은 `http://localhost:3000`, 로그인 암호는 `.env.compose`의 `APP_PASSWORD` 값입니다. 종료할 때는 다른 터미널에서 아래 명령을 실행합니다.

```powershell
docker compose --env-file .env.compose down
```

Docker의 DB와 기본 로컬 실행의 DB는 별개이며 원고가 자동으로 옮겨지지 않습니다. `down -v`는 저장된 DB volume까지 삭제하므로 원고를 보존해야 할 때 사용하지 않습니다. Ollama 연결에 문제가 있으면 컨테이너에서 호스트의 `host.docker.internal:11434`에 접근할 수 있는지 확인해야 합니다.

</details>
